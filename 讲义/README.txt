西综讲义阅读页（看板点页码打开的就是这里）
==========================================

从网站根目录打开
----------------
不要直接双击本文件夹的 index.html（file:// 方式浏览器不允许读取本地 PDF）。
请回到上一级「306-All」目录，双击「启动网站.cmd」，然后在浏览器打开：
    http://127.0.0.1:8787/
先看到进度看板，点任意任务右侧的蓝色页码 Pxx（或功能栏「打开讲义」）就会进入这里，
并自动定位到讲义对应的那一页。

页面里有什么
------------
- 左侧 5 个科目按钮：生理学、病理学、内科学、外科学、生物化学。
  其中「外科学」把上、下两册合成了一个科目：目录按 一~六 章连续排列。
  「生理学」为方便线上部署（单文件不能超过 GitHub 的 100MB 限制）拆成了上、下两册，
  内容与页序完全不变，目录仍按 一~十二章 连续排列。
- 选中生理学或外科学时，科目按钮下方会出现「上册 / 下册」切换按钮，可手动换册；
  目录条目右侧的灰色小字会标「上·PDF x」或「下·PDF x」，点下册的条目会自动切到下册 PDF。
- 目录条目上：
    · 绿色小标签 p.41  = 讲义页码（与进度看板里的 P41 完全一致）
    · 右侧灰色小字 PDF 41 = 合订 PDF 的实际页序
  点击任一目录条目，右侧直接滚动跳到对应的 PDF 页并高亮。
- 顶部工具栏：返回看板、上一页/下一页、输入 PDF 页码跳转、缩放、打开原始 PDF。
- 每科（分册科目按分册分别）会记住上次看到第几页；切换科目再切回来，会回到原来的位置。

快捷键
------
← / →        上一页 / 下一页（PageUp / PageDown 同效；外科翻到册末会自动进下一册）
Home / End   跳到当前分册首页 / 末页
[ / ]        切换到上一科 / 下一科

目录页码是怎么对上的
--------------------
- 目录内容来自讲义 .md 里自带的目录表格（标题 + 讲义页码）。
- PDF 实际页码优先用 PDF 自带的书签（outline）确定，再与 md 目录逐条做标题对齐；
  生理 PDF 没有书签，则用每页文字里的“核心精讲 · 小节名 / 专题串联 · 小节名”标题定位。
- 合订 PDF 里夹了未编号的封面、目录页、导图页和分隔页，所以 PDF 页码通常比讲义页码大
  2~14 页不等，这是正常的；一切以“点击跳过去看到的页面”为准。
- 极少数目录条目在 PDF 里没有对应书签，页码是按相邻条目推算的（误差通常在 1~3 页内）。
  病理学第四~七章、生理学绪论/能量代谢章在 md 目录里本身没有再细化小节，所以这几章只显示章节级入口。

文件结构
--------
index.html              页面结构
css/style.css           样式
js/app.js               阅读器逻辑（目录跳转、按需渲染、科目/分册切换、缩放等）
data/toc-data.js        目录数据（md 目录 + PDF 页码映射；生理/外科各分两册）
assets/*.pdf            7 个 PDF 分册（生理上/下、病理、内科、外科上/下、生化）
assets-original/        原始整本 PDF 备份（本地保留，不参与 GitHub 部署）
vendor/pdfjs/           pdf.js 渲染引擎（4.4.168）与字体 cmaps

技术说明
--------
- 纯静态网页 + pdf.js，不依赖网络。
- 打开时不会整本下载 PDF：只按 HTTP Range 读取「当前页 + 目录索引」需要的那一小段数据，
  所以 80~100MB 的分册也能一两秒打开第一页（旧版要等整本下完）。
  滚动到哪一页才取哪一页，离开较远的页会释放画布；网络抖动导致分段请求失败时会自动重试一次。
- 页面尺寸也是按需获取：先用第 1 页的尺寸排版，其余页先占位，滚动到时再取真实尺寸，
  所以不用像旧版那样先遍历全部 300~400 页（那等于把整本 PDF 拉下来）。
- 同时只加载一个科目的 PDF，切换科目时会销毁上一本，避免同时占用大量内存。
- 要求托管平台支持 Range 请求（GitHub Pages、Nginx、本项目的 serve.py 都支持）。
  如果平台不支持，pdf.js 会退化成「先下整本」，速度会明显变慢。
- 所有 PDF 分册都小于 100MB，可以直接提交到 GitHub（单个文件上限 100MB）；
  assets-original 里的整本备份只在本地保留，已写进 .gitignore。

常见问题
--------
- 打开后一直显示“正在加载”：确认网站根目录的服务器还在运行（启动网站.cmd）；
  端口被占用时可在 serve.py 里换端口，再改「启动网站.cmd」里的地址。
- 页面提示“PDF 加载失败”：确认讲义/assets 里的 PDF 没有被移动/改名，
  且是通过 http://127.0.0.1:8787/ 打开而不是 file://。
- 目录里 p.X 与 PDF X 不一致：属正常现象，原因见上面“目录页码是怎么对上的”。
